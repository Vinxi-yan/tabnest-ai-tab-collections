# TabNest AI 标签合集 v0.5.3

Chrome 侧边栏标签合集工作区，支持保存当前标签、按窗口或全部窗口保存合集，以及拖拽、右键移动、批量管理、归档、导入导出和待办。

## 安装与使用

1. 使用 Chrome 114 或更新版本。
2. 下载并解压本仓库，或将仓库克隆到本机。
3. 打开 `chrome://extensions`，开启右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的目录。
5. 点击扩展工具栏中的 TabNest 图标，打开侧边栏。

项目使用原生 HTML、CSS 和 JavaScript，无需安装依赖或构建。

升级前建议使用插件的导出功能备份数据。覆盖原扩展目录后，在扩展管理页面点击「重新加载」；更换加载目录可能改变扩展 ID，使旧数据不再显示。

## 智能整理与数据存储

当前「AI 整理」由本地规则实现，根据标签标题和 URL 进行分类、命名与去重，无需 API Key，也不调用远程大模型。合集和待办等状态保存在浏览器的 `chrome.storage.local` 中，可通过导入导出功能迁移。

扩展请求 `tabs`、`storage`、`sidePanel` 和 `contextMenus` 权限，分别用于管理标签、保存状态、展示侧边栏和提供网页右键操作。

## 源码结构

- `manifest.json`：扩展配置与权限声明。
- `background.js`：后台服务、侧边栏入口和右键菜单。
- `sidepanel.html`、`sidepanel.css`：侧边栏界面和样式。
- `sidepanel.js`：合集、待办、导入导出及界面交互。
- `ai.js`：本地智能整理规则。

## 修复内容

### 彻底移除默认「收件箱」

v0.5.2 仍有一个遗漏：
`sidepanel.js` 的默认状态中还预置了一个空的「收件箱」。

因此在以下情况会重新出现：
- 用新的解压目录加载扩展
- 扩展 ID / 本地存储发生变化
- 没有历史 TabNest 数据

v0.5.3 已将默认状态改为：

```js
collections: []
```

所以全新安装后应显示：

`0 个合集 · 0 个已保存标签`

而不是：

`已置顶 → 收件箱`

## 什么时候才创建标签合集

只有用户主动执行：

- 保存标签
- 窗口存为合集
- 全部存为合集
- + 新建合集
- 新建时间合集并移动

才会创建标签合集。

默认名称继续为：

`2026年9月28日 周一 15:58:32`

## 旧数据处理

如果历史数据中还存在名为「收件箱」的合集：

- 空收件箱：自动删除
- 有内容的收件箱：改为历史时间名称，标签保留
